# v1.7.0 多线路自动更新验收

目标：某一条连接或 GitHub API 失败时，继续尝试可用线路，保留直接安装能力。

## 路由

- 查版本：首选连接的官方 API → 官方 Releases 网页 → 直连/系统备用连接。
- API 处于限流等待时：只跳过 API，仍读取官方网页；不通过更换出口重复请求受限 API。
- 下载：官方首选连接 → 官方直连/系统备用 → gh-proxy.com → ghfast.top。每个代理也可使用首选/直连连接。
- 版本与 SHA-256 只取自官方 API 或官方 HTTPS Releases 附件行。下载代理只传输附件，不能提供信任依据。
- 设置中可以关闭第三方下载代理。自动备用连接可能改变本工具出口，但不会修改 Windows / Chrome 设置。

## 精确性

- 网页重定向必须留在固定仓库的 latest/tag/expanded_assets 路径。
- 哈希绑定唯一目标附件的 li 行，拒绝相邻 ARM64 哈希、重复附件、缺失/歧义摘要。
- 网页显示 13 MB 等近似大小不作精确校验依据。下载学到的大小仅在官方 SHA-256 通过后保存。
- 重试时丢弃本次半包；从零使用下一线路，不拼接不同来源内容。
- 失败或用户取消时不替换现用程序。

## 测试

新增用例先复现：旧网页解析正则不完整、可能选择第一条哈希、API 等待阻断附件、未知大小下载失败。
保留既有核心/网络/UI/DPI 测试，不弱化精确的 403 和冷却提示断言。
新增离线集成覆盖 API 403→官方网页、已有限流→网页、系统失败→直连、官方失败→代理、坏哈希→下一代理、全部失败清理、取消和重定向白名单。

- 官方网页摘要：6291de97f030e965fabd361418c349f5c0b390e46d55b5fa806cf967f5201a38。
- 官方直连、gh-proxy.com、ghfast.top 分别完整下载同一 ZIP，大小均为 18,186,399 字节且摘要相同。
- 三份包都通过解压、PE 版本/架构/产品名检查；隔离文件夹中的备份/原子替换通过。
- 没有执行下载的 CC Switch，也没有替换用户实际程序或数据库。ARM64 实机未验证。
